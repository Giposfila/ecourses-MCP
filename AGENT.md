# AGENT.md — SFU eCourses MCP Server

## 0. Назначение и приоритеты

Ты — инженер-разработчик Python. Твоя задача — **реализовать и протестировать полноценный локальный MCP-сервер для личного аккаунта студента на `https://e.sfu-kras.ru/` (Moodle, еКурсы СФУ)**, используя лежащий рядом исходный, уже проверенный скрипт **`sfu.py`**. Не ограничивайся планом, примером кода или каркасом: создай рабочий проект, документацию, проверки и инструкции подключения. Работай в текущем каталоге проекта. Прежде чем изменять файлы, прочитай `sfu.py` целиком.

**Принцип:** сохранить успешно протестированную логику, а не переписать её предположениями об API Moodle. Не менять данные на сайте. Первая версия — **только чтение**.

Приоритеты: (1) безопасность учётных данных и сессии; (2) корректность данных; (3) устойчивость к отсутствующим/частично доступным курсам и заданиям; (4) корректный протокол MCP; (5) удобство разработки и запуска.

## 1. Реальный контекст и подтверждённые исследования

### Платформа

- Сайт: `https://e.sfu-kras.ru/` — Moodle с доработанной темой/интерфейсом СФУ.
- Вход через HTML-форму `POST https://e.sfu-kras.ru/login/index.php` с полями `username`, `password`, `logintoken`, `anchor`. `logintoken` извлекается из формы `form#login input[name="logintoken"]` после первоначального GET в **той же** сессии `requests.Session`.
- На практике локальный `sfu.py` смог войти и получить страницу `GET /my/`, а затем прочитать курсы, оценки и задания. Важное уточнение: вывод «Страница личного кабинета получена» сам по себе не является криптографическим подтверждением авторизации — в итоговой реализации проверяй реальный доступ к авторизованной странице, отлавливай редиректы и страницу логина.
- В оригинальном скрипте используются `SFU_USERNAME` и `SFU_PASSWORD` из переменных окружения. **Никогда не запрашивай или выводи пароль, cookies, `sesskey`, `logintoken` в лог, stdout или ответы MCP.** Не записывай их в git.
- В Linux пользователя ранее наблюдалась проблема локального DNS: `socket.gaierror: [Errno -2] Name or service not known`. Для диагностики использовался IP `193.218.139.145`, увиденный в DevTools, и пользователь указывал сопоставление в `/etc/hosts`. Не хардкодь этот IP и не отключай TLS-проверку. DNS — вне функциональности MCP; задокументируй troubleshooting.

### A. Список курсов — подтверждённый AJAX-метод

- Адрес: `POST https://e.sfu-kras.ru/lib/ajax/service.php`.
- Query string: `sesskey=<действующий sesskey>&info=core_course_get_enrolled_courses_by_timeline_classification`.
- JSON request body — массив вызовов, например:

```json
[
  {
    "index": 0,
    "methodname": "core_course_get_enrolled_courses_by_timeline_classification",
    "args": {
      "offset": 0,
      "limit": 48,
      "classification": "all",
      "sort": "fullname",
      "customfieldname": ""
    }
  }
]
```

- Указанные аргументы были видны в DevTools. Другие аргументы могли быть свёрнуты; рабочий `sfu.py` успешно получил 9 курсов с показанным набором. В случае изменения ответа/ошибки — сравни с реальным браузерным Payload, а не угадывай.
- Ответ: JSON-массив с объектом вида `{"error": false, "data": {"courses": [...], "nextoffset": 9}}`.
- Полезные поля курса: `id`, `fullname`, `shortname`, `viewurl`, `startdate`, `enddate`, `progress`, `hasprogress`, `coursecategory`, `hidden`, `visible`.
- Важна **пагинация** и защита от зацикливания: `limit`, `offset`, `nextoffset`, пустые страницы, повторы, дедупликация по `id`, разумный максимум страниц. Не считай 9 окончательным числом курсов пользователя.
- `sesskey` исходный код извлекал из авторизованной HTML-страницы `/my/` regexp `r'"sesskey"\s*:\s*"([^"]+)"'`; это проверено на данном сайте, но может измениться. Сделай более устойчивый разбор и понятную ошибку, не показывая секрет.

### B. Оценки курса — подтверждённый HTML

- `GET https://e.sfu-kras.ru/grade/report/user/index.php?id=<course_id>`.
- Таблица: `table.user-grade` (на тестовом курсе классы `table generaltable user-grade`).
- Колонки: `Элемент оценивания`, `Оценка`, `Диапазон`, `Место`, `Отзыв`, `Вклад в итог курса`.
- Строки таблицы смешанные: заголовки курса/категорий, тесты, задания, итоги категории, рекомендованная и итоговая оценка. Не относить итоговые строки к заданиям. Не интерпретировать проценты/прогресс как оценки.
- Для извлечения полей исходный код использовал `row.find_all(["th", "td"], recursive=False)` и `get_text(" ", strip=True)`, удаляя интерфейсные элементы (`.accesshide`, `.sr-only`, ссылки/кнопки меню в ячейке оценки) и шум `Действия`, `Анализ оценок`, а также префиксы `Тест`, `Задание`, `Итоговая оценка`, `Вычисляемая оценка`. Усовершенствуй этот парсер, не полагаясь только на замены строк, и не изменяй DOM повторно, если нужно несколько проходов (BeautifulSoup-объекты создавай заново или копируй).
- Прочерк `-`, пустая ячейка и отсутствующая оценка -> `null` / `unknown`, а **не** 0 и **не** «не сдано». Сохраняй строковые оценки вроде `не зачтено`; числовую оценку выдавай дополнительно, только если её можно однозначно преобразовать.
- Реальные извлечённые данные тестового курса 41121 (значения только на момент наблюдения): входной тест 8/10; тест 1 — 10/10; тест 2 — 10/10; тест 3 — нет оценки; лабораторная 1 — нет оценки; лабораторная 2 — 8/10; лаб. 3/4/8 — нет оценки; итог категории тестов 28/80; итог категории лабораторных 8/80; рекомендованная оценка `не зачтено`; итог за курс 37 при диапазоне 1–172. Важно: не вычисляй общий итог простым суммированием, Moodle может применять свои формулы.

## 2. Требуемый конечный результат

Собери проект, в котором можно запустить MCP-сервер через `stdio` и подключить его к совместимому MCP-клиенту. Ожидаемые функции:

1. `get_courses()` — все доступные студенту курсы с `id`, `name`, коротким названием и URL; пагинация без дублей.
2. `get_grades(course_id: int)` — оценки **одного** курса, со строками, категорией/типом, исходной оценкой, числовой оценкой при возможности, диапазоном, признаком итогов и предупреждениями.
3. `get_assignments(course_id: int)` — задания **одного** курса с названиями, URL/`module_id` (если есть), `due_date_raw`, нормализованным сроком (если достоверен), состоянием ответа, оценкой и предупреждениями.
4. `get_upcoming_deadlines(days: int = 7, include_submitted: bool = false)` — выборка дедлайнов со всех доступных курсов, сортировка по дате, фильтрация по статусу **только если статус известен**; неизвестный статус не называй «не сдано». Ограничь `days` разумным диапазоном, напр. 1–365. Добавь сведения о нераспознанных датах и ошибках отдельных курсов.
5. Полезно, но необязательно: `get_assignment_details(module_id: int)`.

**Контракты инструментов:** JSON-сериализуемые словари/списки, стабильные имена полей, понятные ошибки и warnings. **Никаких логинов, cookies, токенов или сырых HTTP-заголовков в ответах.** Ошибка одного курса не должна ломать глобальный запрос по всем предметам. Не выдавай обещания «все несданные» там, где сайт не раскрывает статус. Не раскрывай внутреннее содержимое закрытых курсов/данных третьих лиц.

## 3. Инженерные требования

### Код и архитектура

- Текущий `sfu.py` — **проверенная исходная точка**. Прочитать, сохранить его основные URL, селекторы и схему логина; отделить `SFUClient` (HTTP, сессия, парсеры) от `server.py` (объявления FastMCP) и CLI/ручного тестирования. Убрать побочные эффекты при `import`.
- Использовать `requests`, `beautifulsoup4`, `mcp` (`FastMCP`). Python 3.10+ предпочтителен; фактический локальный запуск исходника был под Python 3.14. Не опираться на непроверенные API сторонних пакетов — при необходимости проверить их установленные версии.
- `mcp.run(transport="stdio")` (или актуальный эквивалент установленной библиотеки).
- Не писать диагностику в stdout MCP-процесса: stdout зарезервирован под протокол; диагностические сообщения в stderr/logging. Не выводить JSON дампы с секретами.
- Авторизация: `requests.Session`; GET формы → извлечь новый `logintoken` → POST логина → подтвердить результат авторизованным запросом; переавторизация при истечении сессии, ограниченное число повторов. Обрабатывать таймауты, сетевые ошибки, неправильный логин, недоступность курса, HTTP-ошибки. Не пытаться обходить CAPTCHA, MFA, rate limit или ограничения Moodle; если появились — сообщить пользователю.
- Учётные данные из `SFU_USERNAME`, `SFU_PASSWORD` при работе; можно предложить безопасное локальное хранилище секретов как альтернативу. Никогда не помещать пароль в CLI-аргументы и не добавлять реальные `.env` в git. Если поддержишь `.env`, используй gitignore и пример `.env.example` без реальных секретов.
- Все запросы только к ожидаемому домену `e.sfu-kras.ru`, TLS-верификация включена. Не следовать неконтролируемым редиректам на произвольные хосты с секретами. Разумные таймауты, ограничение числа запросов и кэш/TTL для повторяющихся обращений, чтобы не нагружать университетский сайт.
- Валидировать целочисленные `course_id`, `module_id`, параметры фильтров. Не формировать URL от недоверенной строки.
- Код должен устойчиво работать, если Moodle отдаёт HTML вместо ожидаемого JSON, пустой список, лишние столбцы, элементы навигации/действий, локализованный текст, частичный ответ или ошибку API.
- Периодическая проверка сроков возможна позже; **не создавать автоматические уведомления/мониторинг** как скрытый фоновый процесс в первой версии.

## 4. Готовность проекта (Definition of Done)

Проект считается готовым, если:

- [ ] Пользователь может установить зависимости и задать учётные данные локально (для fish shell в README есть пример безопасного интерактивного ввода).
- [ ] `python server.py` запускает MCP stdio-процесс без лишнего вывода в stdout.
- [ ] MCP-клиент может обнаружить минимум 4 инструмента и вызывать их независимо.
- [ ] Курсы загружаются динамически; нет хардкода `course_id=41121` в рабочей логике.
- [ ] Оценки и задания извлекаются и возвращаются в стабильной JSON-структуре, когда у пользователя есть доступ к таблицам.
- [ ] Дедлайны агрегируются по доступным курсам без неверных предположений о годе, статусе и часовом поясе; неоднозначные случаи помечаются.
- [ ] Ошибка/отсутствие таблицы одного курса не приводит к потере результатов остальных.
- [ ] Реализованы тесты без использования персональных учётных данных.

## 5. Порядок работы агента

1. Прочитай `AGENT.md` и соседний `sfu.py` целиком. Определи текущие работающие блоки (логин → оценки одного курса → overview заданий → AJAX курсы), проверь зависимости.
2. Спроектируй краткую схему `SFUClient`, методов и моделей данных; затем **реализуй её**.
3. Создай рабочие файлы проекта и tests/fixtures; сохрани общую совместимость с поведением исходного кода.
4. Запусти офлайн проверки, исправь ошибки. Не придумывай ответы сайта, если доступ к нему отсутствует.
5. В итоговом ответе кратко перечисли созданные файлы, команды запуска и подключения, проверенное, известные ограничения и что пользователь должен сделать для live-проверки.

### Пример желаемого пользовательского опыта

После подключения MCP к ИИ пользователь сможет спросить:

- «Какие предметы у меня есть на еКурсах?»
- «Покажи оценки по информационно-вычислительным сетям».
- «Какие работы имеют дедлайн в ближайшие 7 дней?»
- «Какие работы отправлены, но ещё не оценены?»

Не обещай точный ответ на «какие несданные работы», если Moodle возвращает неизвестный статус. Не выполнять сдачу, редактирование оценок, скачивание персональных файлов без запроса или другие изменяющие операции.
